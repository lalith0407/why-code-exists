## Idea-level holes (first)
1. **The "proof" is circular.** In `src/engine/investigate.ts` (draft_tests and patch steps) one LLM writes the fakes, the reproduction test, the decoys AND the patch. A `proven_false` verdict only shows that a model-built simulation agrees with a model-written claim. Real code, real data and the real runtime are never exercised (`wceDb` is a fake ORM). The Zetaris step admits the same thing about itself (`src/engine/zetaris-step.ts:7-8`: "observations are produced by the harness fakes ... not a production measurement").
2. **Narrow input precondition.** It needs the AI-agent session transcript that wrote the crashing function (`investigate.ts`, `no_provenance` path). Most production incidents don't come with one. The pain is real but the addressable slice is small today.
3. **The held-out inputs leak the diagnosis.** `cases/heldout-vote-race/error.json` says outright that "the same user had a second toggleVoteAction request ... in flight (31 ms apart)". Real error logs don't carry that sentence. And even with these hints, the engine still failed.

## Held-out generality (the decisive evidence)
The success criteria (`docs/heldout-success-criteria.md`) were frozen before the run. The results:
- vote-race: **patch_ineffective**
- slack-multiline: **not_reproduced**. The claim also named the wrong cause (payload parsing, not the regex `.`/`$` problem).
- xirr-short: **harness_error**. The claim also named the wrong cause (convergence, not the [-0.9, 5.0] clamp).

**That is 0/3 successes and 1/3 correct claims.** Only vote-race's claim is roughly right. The new generic engine has never produced a successful result on an unseen case. The earlier wins (invite, SSRF, Slack-retry at 3/3) came from the old per-bug pipelines, which commit b7cef2b deleted.

I did not run it on an unseen public repo: that needs a matching agent transcript, which public repos don't ship. This is itself a generality limit.

### Findings
1. **Hard-coding: clean in the engine.** Grepping `src/` for case identifiers (toggleVote, parsePulseCommand, _xirr, invite, ssrf, slack, P2002, pulseboard, clamp) finds only a scrub comment (`src/scrub.ts:40`). The case-specific values sit in tests only (`tests/provenance.test.ts:43-58`, transcript line numbers for invite and SSRF), and those are legitimate regression fixtures. Not blocking.
2. **Tuning to evals: minor, not blocking.** The test-writing prompt's polarity examples mirror the dev cases: "created twice" (Slack retry) and "wrongly gained access" (invite) (`src/engine/investigate.ts`, SYSTEM_TESTS). The freeze holds. Tag `generalize-frozen` is b7cef2b (19:29 PT). 089b755 (19:37) adds only cases and criteria (`git diff generalize-frozen 089b755 -- src` is empty). ed4a9e6 and 3d2aac2 add only results and docs. No cases or criteria were edited or dropped after the results. The pre-freeze dev cases (invite, SSRF, slack-retry) were iterated on for more than 10 commits, but those are not presented as held-out.
3. **Leakage: BLOCKING (for the held-out claim).** `cases/heldout-vote-race/error.json` (message field) states the cause: "the same user had a second toggleVoteAction request for the same feedback in flight (requests 31 ms apart)". The claim step receives `err.message` verbatim (`src/engine/investigate.ts`, claim call `user.error.message`). This would inflate a success; here it didn't, because the case failed. The patcher never sees the tests, and the test writer never sees the patch. That part is OK.
4. **Circular proof: BLOCKING.** One provider (`checkerProvider`, default openai) writes the fakes, the tests and the patch (`investigate.ts` draft_tests, repair_harness and patch calls). The mechanism gate is the same provider by default. The callee is faked away: in slack-multiline the real buggy helper `parsePulseCommand` was replaced by a model fake, so the real bug could never reproduce (docs/heldout-results.md row 2, confirmed in `artifacts/heldout/slack-multiline/harness-original.mts`). The fake DB has **no unique-constraint enforcement and a no-op `$transaction`** (`src/engine/fakedb.js.txt:77`, plus create/upsert at :63 with no uniqueness check), although the prompt tells the model the fakes raise unique-constraint errors "where the real client would". So a correct transactional or upsert fix can never make the vote-race repro fail. "Proven" is bounded by how faithful the fakes are, and the fakes are known to be unfaithful.
5. **Stubs and silent fallbacks: BLOCKING (sponsor).** Zetaris runs only when the verdict is proven_false and `--zetaris` is passed. Its errors are caught into `{verdict:"error"}` (`src/bin/investigate.ts:25-28`), and it has never run on a held-out case. Meterless soft-fails to local JSON when the external bridge (`src/lesson/meterless.ts:26`, another repo) is down. Both sponsors can be absent with the run still "succeeding". The main path fails loudly on LLM errors, which is good.
6. **Band-aids: BLOCKING (honesty of the repair step).** The comment says "allow ONE prelude-only repair. Tests stay identical" (`src/engine/investigate.ts:244`). The code loops up to **2** repairs and **replaces the tests**, `draft.tests = fix.tests` (`:261`), so a repair can rewrite the assertions. The prompt asks it not to "weaken" them (`:147`), but nothing enforces that, and the frozen sha256 is computed after the repair. There are no case-specific branches.
7. **Synthetic data presented as real: BLOCKING (docs).** The Zetaris "evidence" rows are harness-fake observations plus hand-written `cases/*/data/*.json` (e.g. `heldout-vote-race/data/request_log.json`). The code comment is honest (`src/engine/zetaris-step.ts:7-8`), but the README calls it "Zetaris SQL evidence" and one of "four evidence sources" (README.md:15, 41) without that caveat.
8. **Overstated claims: BLOCKING.** The README documents deleted commands, files and results (README.md:43, 74, 87, 143 cite `demo:*`, `src/assume`, `src/prove/check.ts`, "proven 3/3") and omits the 0/3 held-out result. The parent brief's claim that Meterless "approves or blocks spend" is false (`src/engine/llm.ts:33-34` is a local counter; `src/bin/approve.ts:11-12` is a human lesson approval).
